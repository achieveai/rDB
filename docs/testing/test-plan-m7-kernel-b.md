# M7 kernel-b test plan: R1 replication, L1 protection, F1 recovery

Status: draft for Critic round 2. Date: 2026-09-20.
Scope: the three kernel-b spike packages of `crates/rdb-core` (`replication.rs`, `protection.rs`,
`recovery.rs`) and their `rdb-sim` scenario files.
Authority order: charter (`teams/kernel-b/charter.md`) > ledger rulings (B-R3..B-R28, V-R14, F-R1..F-R12)
> `docs/ADRs/rdb/0005`, `0006`, `0009` > `teams/kernel-b/design.md` (architect design, correction round 1
applied; round 2 in progress) > `teams/kernel-b/critic-design.md` re-review (K-B-35..41, QC-10..14).
Companion: `docs/testing/test-plan-m7-verification.md` (foundation plan; format model, taxonomy §2,
anti-flake rules §11, gate checklist §13). This plan continues its Q-row numbering at Q-46 (kernel-a owns Q-41..Q-45, ruling B-R30).

Row prefix `M7B-NN`. One row is one named test `m7b_NN_<name>`. Numbering is flat across the three
test files (architect handoff Q10 default). Existing ids are never renumbered. The former held rows
(`M7B-H<n>`) were re-issued as M7B-120..137 when the holds lifted (§9); the H→id map is in the handoff.

## 2. Taxonomy, rules and gate

Classes and budgets follow the verification plan §2: `unit` under 100 ms, single module, no scheduler;
`sim` under 2 s, `rdb-sim` virtual scheduler, one scenario; `campaign` under 60 s, many seeds, numbers
recorded. Rules carried unchanged: no wall-clock assertion; a near-miss twin differs by exactly one fact;
`Unavailable` is never a pass; one row is one test; row id prefixes the test name.

Dependency column values: `none` (kernel-only, buildable against landed C0 at `8a23b1d`), `F:<cap>`
(foundation seed capability, e.g. `F:M1 storage faults`, `F:H1 harness`, `F:T1 transport`), `A:<seam>`
(kernel-a seam, e.g. `A:P1 QualifiedPrefix`), and the four numbered C0 asks from the architect's
handoff §15, cited by id: **CB-1** the `EventKind::Kernel`/`EffectKind::Kernel` carrier pair (BA-10);
**CB-2** `AppendReject::NeedPrefix{have, head_digest}`; **CB-3** `AckRejectReason` plus seven named
variants (BA-4); **CB-4** the non-reject `AppendOutcome` variants `Busy{accepted_through}`,
`AlreadyHave`, `ProbeDigestAt{seq}`; and **CB-5**, which this plan proposes in round 4 and the
architect's handoff does not yet carry: `BlockReason` widened by `NoEligibleRegular`,
`ControlUnavailable` and `ControlUnknown`. §13 names every row waiting on each. `none` on a row that rides a kernel-internal event or
effect means "no seam beyond BA-10's carrier", which §13 lists once for all of them rather than repeating
it on 130 rows.

Every row below cites the design section (`D §x.y`) and the ADR clause it proves (`0005 §n`, `0006 §n`,
`0009 §n`, charter `C`, spike `S §5`). Row literals follow **landed C0 at `8a23b1d`**: `AppendAck` (not
`ProgressAck`), `ReplicaRole::RegularSecondary` (not `Regular`), `Event.at` (not `ev.tick`),
`ControlEffect::Cas{key: ControlKey::Partition(id), expected, value}`, `ControlEvent::CasResult{key,
outcome: CasOutcome}`. Deltas from the design's names are §15.

- **A3** Effect-vector assertions use index equality on the whole vector (`assert_eq!(effects, vec![..])`) unless the row says "contains"; "contains" is used only where an unrelated telemetry effect may interleave (M7B-30, 41, 54). **No row asserts an empty vector** (T-B-05, BA-2): `assert_eq!(effects, vec![])`, `effects.is_empty()` and equivalents are banned, because under BA-2 an empty vector is a defect, not a pass. Where the design says "no effect", the row asserts exactly one `Ignored{reason}`. Q-57 greps for the banned forms.
- **A4** Rows that feed "every event kind" build the list from an exhaustive `match` helper in the fixture so a new variant fails to compile the fixture, not silently pass (M7B-28, 84, 119).
- **A5** `Unavailable` is a distinct outcome: a row whose seam is a stub calls `unavailable!("<seam>")`, which marks the test skipped-with-reason in the JSONL; it is never `Ok(())`. **Ownership** (T-B-04): the macro is the *verification* plan's (V-R7) and lives with the shared `#[retcd_test]` harness in `crates/rdb-sim/tests/support/`, which foundation owns — kernel-b consumes it and does not define a second copy. If it has not landed when a kernel-b row needs it, the row uses the harness's existing skip path and the handoff records which; it never degrades to a passing assertion.
- **A6** Two-field ladder-order rows (M7B-15, 33) fix the lower field in the same test and assert the higher code appears, so a ladder reordering fails rather than passes by coincidence.
