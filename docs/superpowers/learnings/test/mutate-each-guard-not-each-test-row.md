## Problem
S5 reported 25 developer mutants, all red. Two guards still had no test:
- the GC scan's stop at the end of the chunk prefix;
- the version check on `delete_blob`.

Deleting either one left the whole suite green (103 tests passed with the delete guard removed). The tester found the first. The reviewer found the second.

S4 reported 81 developer mutants, all red. The tester deleted 5 more guards from the code:
- one survived: the `OrphanElement` refusal when a Replace moves an item out of its block;
- one went red only on a counter ("every rule was exercised" saw 0 retires), not on a value or record check;
- one went red only because the surviving guard above caught its side effect.

## What didn't work
- Mutants chosen from the test rows. Each mutant broke something a row already checked, so every one went red. That proved the rows ran, not that every guard was pinned.
- A guard list carried forward from earlier slices. S4's 81 came from the W1 and W2 lists, re-pointed where the code moved. The guard that survived was not on them.
- Counting a red test as a kill. A test that goes red on a counter, or through another guard, stops being red when the random draws or that other guard change.
- Restoring a mutated file by copy on Windows. `copyFileSync` keeps the backup's old mtime, so cargo does not rebuild and the next run uses the mutated binary. In S4 four mutants showed false extra reds.

## Solution
Before the thumbs-up, list every guard in the changed code as it is now:
- each `if … break`;
- each `return Err`;
- each emitted precondition (`Condition`).

Delete each one once. Name the test that goes red **and the assertion that fired**. A guard with no red test, or one that dies only on a counter or through another guard, needs a direct test before the thumbs-up.

After each mutant: restore the file, `touch` it, and check its md5 against the original.

## Why it works
A mutant list built from the tests is limited to what the tests already cover, so it cannot show a gap. A list built from the guards includes every place the code can refuse or stop. Any guard with no red test is a gap. Naming the assertion separates a test that checks the guard's effect from one that fails by accident.
